## 現況總評（先講結論）

**強項**：三個角色 agent（小工程 / 小排版 / 小畫家）寫得好——有職責邊界、有「絕對不要做的事」清單、有量化風格規範、太魯閣族文化審查протокол 尤其扎實。

**淨結果**：三個 agent 各自把同一套安全規則重抄一遍，主對話又習慣親自吞巨檔——這正是下面三個漏水點。

## 🔴 痛點 #1（最浪費 Token）：指揮官親自吞巨檔 ＋ 規則三重複製

### 物理事實（可驗證）
- 主檔 `hunter-truku-v2.html` = **82 KB**（HTML+CSS+JS 全塞一檔），`truku_vocab_final.json` = **362 KB**，`seed_data.js` = **178 KB**，`backend/vocab_seed.js` 同級。
- 主對話只要 `Read` 其中一個巨檔**一次**，就吃掉數萬 token；改一次 `hunter-truku-v2.html` 常要全檔進 context。
- 三個 agent 定義各自內嵌了幾乎逐字相同的「部署安全規則 / 專案背景 / DB schema / 本機測試環境」段落（每個 agent 重複約 1.5–2 KB）。改一次規則要同步改三處，且每次叫用 agent 都重載一份。

### 為什麼會漏水
Token 花在「重複載入已知資訊」上，而非推理。巨檔進主 context 後，後續每一輪對話都要拖著它，等於持續課稅。三份規則副本遲早不同步（drift），弱模型會照到過期那份。

### 阻斷方案（程序級——註：非物理級，見文末誠實條款）
1. **主對話硬門檻**：主對話**禁止**主動 `Read` 單一檔案 > 400 行或 > 25 KB，也**禁止**一次讀 3 個以上檔案來「找東西」。這類工作一律派 Subagent（見 [`C`](C-model-dispatch.md)），主對話只收「路徑 + 關鍵行號 + 一段結論」。
2. **巨檔黑名單明列**：`CLAUDE.md` 的「巨檔清單」直接點名上面四個檔，看到就知道要派工。
3. **DRY 單一真相源**：安全規則、DB schema、路徑慣例只存 `CLAUDE.md` **一份**；三個 agent 定義刪掉重複段落，改成「見 `CLAUDE.md` 的 X 節」。（本 session 不改動既有 agent 檔以免破壞，改為在 `CLAUDE.md` 建立真相源並於 G 交接信標記此為待辦。）

## 🟠 痛點 #2（最容易失焦）：沒有停損判準，在錯的代碼上原地重試

### 物理事實
- 目前沒有任何「什麼時候該停下換路徑」「什麼時候算做完」「什麼時候該回頭問人」的成文判準。
- 巨檔（見 #1）全讀進主 context 會稀釋任務焦點：模型讀完 362 KB 詞彙 JSON 後，原本的小任務已被淹沒。
- 專案根目錄有 `Codex.md` / `Codex_v2.md` / `Missing_Assets_Codex_v2.md` 三份素材規格、外加一個洩漏的暫存檔 `Usersasd81...extracted.js`（33 KB），掃描時全是雜訊，容易把模型帶偏。

### 為什麼會漏水
弱模型的典型失敗模式是「同一個錯誤方向反覆微調重試」——改一行、跑一次、沒過、再改一行，燒掉整個 window 也沒換思路。缺乏「停損信號」時，模型不會自己喊停。

### 阻斷方案（程序級）
1. **停損檢核表**：[`D`](D-judgment-matrix.md) 提供「方向錯了的 6 個信號」，命中任一即停手、換路徑或熔斷，禁止在同一方案上第三次重試。
2. **兩輪上限硬規則**：同一子任務同一方案最多重試 2 輪（見 [`C`](C-model-dispatch.md) 升降級路徑），撞到就升級或問人。
3. **完成定義（DoD）**：[`D`](D-judgment-matrix.md) 給「真正完成」的量化條件，未滿足不得回報「已完成」。
4. **雜訊隔離**：`CLAUDE.md` 標記哪些是「現行真相檔」、哪些是「歷史/暫存勿參考」，避免掃到過期規格。

## 🟡 痛點 #3（最常引發工具 / MCP / Skills 調用錯誤）：雙 Shell 語法混用 ＋ 權限碎裂 ＋ 環境地雷

### 物理事實
- 本機**同時**有 PowerShell（primary）與 Bash 工具，兩者語法不同（`$env:VAR` vs `$VAR`、`NUL` vs `/dev/null`、`;`/`if($?)` vs `&&`）。混用是最常見的指令失敗來源。
- `settings.local.json` 的 allow 清單有 **84 條**、幾乎全是一次性超specific 條目，且看得到同一指令因引號跳脫不同被重複加入（例如 `grep -E` 出現兩種寫法、node 版本檢查出現多條）。這代表模型過去反覆撞權限牆、每次用略不同的寫法重試。
- `better-sqlite3` 是原生模組，**必須**用專案內免安裝的 `.localtools/node-v20.18.1-win-x64/node.exe`，用系統 node 會編譯失敗噴 cryptic error。
- 本機預覽**一定**要用 `.claude/launch.json` 的 `hunter-backend-local`（port 3001，同源含前端+API），用錯設定會 CORS 或 404。

### 為什麼會漏水
每次工具調用失敗 = 一輪 token + 一次失焦 + 常常引發「換個引號再試」的無效重試循環。權限碎裂讓 allow 清單完全無法作為白名單參考。

### 阻斷方案（程序級 + 建議物理級）
1. **工具鐵律表**：`CLAUDE.md` 用一張表寫死「什麼情境用哪個 Shell、node 用哪支、preview 用哪個 config、生圖用哪支腳本」，附正確指令範例，讓模型照抄不要即興。
2. **權限清單收斂建議**：本 session 依 User 指示**不改 settings**；改為在 [`appendix-recommended-hooks.md`](appendix-recommended-hooks.md) 附一份「結構化 allow / deny 建議稿」，User 願意時可一鍵套用。
3. **失敗即停**：同一指令因語法/權限失敗 1 次，**先讀工具鐵律表核對**，不要盲目換引號重試（Haiku 錯 1 次即升級，見 [`C`](C-model-dispatch.md)）。

## ⚖️ 誠實條款：這套 Harness 的能力極限

**必須讓未來模型清楚知道「制度能保證什麼、不能保證什麼」，否則會對純文字規則產生虛假安全感。**

### 極限 1：目前是「程序級」阻斷，不是「物理級」
User 本次選擇**只用文字規則、不裝 hooks / 不改 settings**。因此上面所有「阻斷方案」都是**靠模型自願遵守流程**，不是靠系統強制擋下。
- 意義：規則能大幅降低出錯率，但**擋不住一個決心違規或失憶的模型**。真正的物理護欄（PreToolUse hook 擋 `scores` 表寫入、擋 `.env` 外洩、擋跳過備份部署）已備妥於 [`appendix-recommended-hooks.md`](appendix-recommended-hooks.md)，**強烈建議 User 日後啟用**。在啟用之前，`scores` 表安全、部署備份只有「流程強制點」保護（見 [`D`](D-judgment-matrix.md) 熔斷表把「部署 / 動 scores 表」列為必停問人事項）。

### 極限 2：模糊的商業美感與品味決策，弱模型注定失敗
拆解 + 隔離驗證能把「有客觀對錯的工作」（邏輯、bug、測試、路徑、schema）逼近高階品質；但遇到**沒有客觀判準的品味題**——「這個配色好不好看」「這句文案順不順」「這張獵人角色的氣質對不對」「這個文化呈現得不得體（灰色地帶）」——弱模型無法可靠判斷，硬做只會產出「看似合理但品味平庸/走味」的結果。

**遇到品味題的強制應對標準（弱模型必照做，禁止自行拍板）：**
1. **不自己選**：不得靜默挑一個方案就往下做。
2. **產出 2–3 個具體可比方案**：能截圖就截圖（用 `preview_screenshot`）、能給文案就並排列出，讓 User 肉眼比。
3. **升級問人**：用 [`D`](D-judgment-matrix.md) 熔斷格式，給 User 一個明確的 A/B/C 選擇題，附每個選項的取捨，而不是開放式「你覺得呢」。
4. **文化敏感題額外加碼**：任何涉及太魯閣族人物/服飾/器物/紋面的品味邊界，一律走小畫家的文化審查流程並回報 User，**不確定就省略不編造**（見小畫家 agent 職責 5）。

> 一句話總結能力邊界：**「有標準答案的，制度能幫弱模型做到接近高階；沒有標準答案的，制度只能幫弱模型認得自己不該獨自決定，然後把選擇權交回給你。」**
