## 第一部分：三件你沒問、但我認為最關鍵的事

### 事 ②：目前最危險的東西只有「文字」在守，沒有「柵欄」在擋
`scores` 表（真實玩家分數，不可逆）、`.env`/金鑰、正式站部署——這三件事現在**只靠模型自願遵守 CLAUDE.md 的 prose**。一個失憶或想抄捷徑的弱模型可以直接違反，沒有任何東西會物理阻止它。
> 我已經把該裝的護欄寫成現成可套的 [`appendix-recommended-hooks.md`](appendix-recommended-hooks.md)（PreToolUse hook 擋 scores 寫入 / 擋密鑰外洩 / 部署前強制備份檢查）。你這次選擇先不裝——這完全合理，但請把「哪天裝上 hooks」放在心上。**在裝上之前，凡碰 scores/部署/密鑰一律走熔斷問人（[`D`](D-judgment-matrix.md) 表 3），不要因為「規則說不行」就以為系統會擋你——不會。**

### 事 ③：你只有一個模型檔位（Opus 4.8），所以「隔離驗證」是你唯一的品質槓桿，而它很貴
既然指揮官和工人都是 Opus 4.8，你無法靠「換更聰明的模型」提升品質。你能拉高品質的**唯一結構性手段**就是 [`C`](C-model-dispatch.md) 第 4 節的**Fresh-Context 隔離驗證**——用一顆沒有確認偏誤的新腦去 read-back / 實跑。
> 但它會多花約一倍 token。**這裡有個致命誘惑：為了省 context 而跳過隔離驗證。** 一旦開始跳，弱模型的自我宣稱就沒有任何制衡，「說做完了其實沒存檔」這類錯誤會回來。請把隔離驗證當成不可省的成本，不是可選的加分項。這是我離開後，你最可能為了省事而放棄、但最不該放棄的東西。

## 第二部分：這套制度在弱模型長期運作下，最可能的腐化方式與預防

| 腐化方式 | 徵兆（怎麼看出來） | 預防機制（已內建在哪） |
|---|---|---|
| **規則漂移（Rule rot）** | 三個 agent 各自內嵌的安全規則，跟 `CLAUDE.md` 正本開始不一致；改了一處忘了另一處 | DRY：`CLAUDE.md` 🔒 節是唯一正本，agent 若衝突以它為準。**待辦**：把 agent 內重複段落改成「見 CLAUDE.md」（見事①的 promote 後續） |
| **驗證侵蝕（Verification erosion）** | 開始出現「我讀過代碼，邏輯正確，完成」這類**沒有實跑證據**的回報 | [`D`](D-judgment-matrix.md) 完成定義規定：無 Fresh-Context 驗收 + 無具體證據 = 自動 **FAIL**，不准回報完成 |
| **靜默違規（Silent violation）** | 模型遇到不方便的鐵律，選擇「假裝沒看到」而非指出矛盾 | [`F`](F-knowledge-iteration.md) 第 4 節：制度與現實衝突要**明講並建議修訂**，偷偷不遵守是最危險的腐化起點 |
| **教訓簿膨脹（LESSONS bloat）** | `LESSONS.md` 變成 100 條沒人看的流水帳，新坑淹沒舊智慧 | [`F`](F-knowledge-iteration.md) 第 3 節量化觸發（40 條/600 行/同主題 3 條）→ 摺疊升格，不刪除 |
| **模板照抄空心化（Cargo-culting）** | 派工模板被填成空泛驗收條件（「做好一點」「確認沒問題」），三件套變形式主義 | [`E`](E-delegation-templates.md) 自檢清單 + 大量正/反例；驗收條件必須「有具體輸入輸出」才算數 |
| **問人校準失衡** | 要嘛什麼都不問硬做（越過熔斷線），要嘛雞毛蒜皮都問（打斷 User） | [`D`](D-judgment-matrix.md) 表 3 明列「哪些**必須**問」；表 3 以外、有客觀對錯的，自己做完再隔離驗收，不要問 |
