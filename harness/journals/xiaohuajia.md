## 2026-07-02 · 從 v1 扁平向量換成 v2 細緻繪本風

一開始我照使用者最早的偏好，把所有素材都走扁平向量插畫風（乾淨線條、單一淺色背景），詞彙插畫也是這樣做的。後來使用者拿了一張參考 mockup 要整個重畫，一開始我以為連詞彙插畫都要跟著換，但使用者很快更正了範圍：**詞彙插畫維持原樣（klokah.tw 外連或既有的 v1 生圖），只有遊戲介面本身（背景、獵人角色、木牌/羊皮紙 UI 框架）換成 v2 風**。我把這條界線寫進了自己的職責規範，因為這種「兩套風格並存」的情況很容易在後續工作中搞混，我後來也真的差點犯了這個錯，得靠這條界線提醒自己。

交棒：任何新素材需求進來，先問「這是詞彙插畫，還是遊戲介面素材」，兩者適用不同風格規則。

## 2026-07-02 · 建立太魯閣族文化安全審查框架

使用者的詞彙表裡有不少實際的傳統器物/服飾詞（`pala` 布裙、`towkan` 背網、`bhniq` 弓等），我意識到這些如果隨便生圖很容易踩到文化挪用的雷。我參考了使用者提供的阿美族視覺文化守則的「流程結構」，但內容整個改寫成太魯閣族專屬版本——絕對不能把阿美族的紅黑配色、情人袋這些事實直接套到太魯閣族身上，那正是原文件警告的「跨族群混用」錯誤。我定了幾條硬紅線：不畫紋面（Ptasan）除非明確確認、不跟泰雅族菱形織紋混用、不跟其他族群符號混用、不確定的文化細節寧可省略也不編造。這套框架後來在好幾次生圖決策裡都被我拿出來用，尤其是關卡圖示那次差點踩雷。

## 2026-07-04～05 · Codex 外部生圖工作流跑起來，回收好幾批 UI 素材

我不直接呼叫圖片生成 API，而是寫規格 md（含 English prompt、負面提示、文化安全審查結論）交給使用者手動貼給 Codex，產出後我負責回收、壓縮、驗證、歸位。這批做了不少：登入畫面的木牌/圖示/分頁按鈕、木雕喇叭按鈕（取代現代 3D icon，做成圓形木盤+金邊+藤蔓+喇叭符號）、L1 音選詞畫面的中央答題面板框/沙漏計時/選項木牌。每張回收後我都會親眼開圖確認：透明背景有沒有做對、有沒有夾帶不該有的文字、風格會不會違和。

## 2026-07-05 · 差點被 mockup 的紅色菱形圖騰騙過去——關卡圖示的文化安全複核

使用者給了一張關卡選擇頁的 mockup，要我評估 5 個圓形關卡圖示。我一眼就看出 LEVEL4 那個是紅色菱形圖騰——這正是泰雅族/太魯閣族的菱形織紋（俗稱祖靈之眼），我們的房規明列不能碰，即使 mockup 是使用者自己找的參考圖也一樣。我沒有照抄，改設計成「畫框+放大鏡+眼睛」的中性版本，跟其餘四張圖示（葉+音波/樹/山峰/暗化鎖）的圓形木框語言保持一致。五張圖的四角都用了同一組孤立裝飾金鉚釘（不是連續織紋，是我們一直以來的房規安全用法），審查通過並生成歸位。

交棒：如果之後有人想「統一」1/2/3 的菱形釘跟 4/5 的圓釘造型，那只是視覺一致性的小瑕疵，不是文化問題，可以之後再重生，不急著現在改。

## 2026-07-05 · 上線前視覺總審 + 診斷「logo 跑掉」的根因

使用者說「視覺上線不能再有遺漏」並回報「選擇 level 那個頁面 logo 跑掉了」，要我分析。我讀了程式碼發現：首頁用一張整合好的 PNG 招牌，但關卡選擇頁是另一套做法——空木牌背景 + CSS 疊字 + 一個用 `position:absolute; left:-108px` 掛在木牌左外側的獨立獵人圖，這隻獵人在窄一點的視窗下會被 `overflow:hidden` 裁掉，這就是「跑掉」的根因。我建議最乾淨的解法是關卡頁直接改用首頁那張整合圖（兩頁一致），但那張圖底部烤死了「太魯閣語」字樣，跟現在 42 語別可切換的情境衝突，所以同時建議連底部那行也一起去掉重生。使用者採納了，我依 v11 規格報了完整的 Codex prompt（含 negative prompt 明確排除各族織紋/紋面/PANGCAH 字樣），使用者拿去生成回收後，我做了三件驗收：圖裡只有兩組文字（族語射手/TRUKU WORD ARCHER）、透明背景四角 alpha=0、比例落在約 2.3:1，確認過關才交給小排版做 A1 換圖。

同一輪我也掃了一遍其餘素材（獵人角色、5 個關卡圖示、木框/沙漏/喇叭）確認無文化風險，唯一的風險點就是「別誤採 mockup 那個紅菱形」。

## 2026-07-05 · 評估 L3 聽打畫面改版——結論是幾乎不用生圖

使用者給了 L3 聽打的 mockup（中央答案格面板+右側播放語音面板+音節點提示），我盤點後發現一個好消息：這個 mockup 需要的素材幾乎全部現成——中央木框可以用既有的 `v2-choice-panel-frame`/`v2-word-card-frame`，右側播放面板同理，喇叭就是我之前生的木雕喇叭放大，答案格凹槽跟音節點用純 CSS 就能做出來。我判斷必生圖數量是 0 張（選配最多 1 張凹槽素材，且我會先報 prompt 才生，不會自己燒額度）。文化安全也過了——葉飾/木框/沙漏/圓點都是中性通用語彙。核心工作量其實落在小工程（把 L3 接上 L2 已有的答案格機制）跟小排版（版面重排），不是我這邊的活。我也提醒了一個遊戲設計取捨：答案格會露出單字長度，等於降低聽打難度，這是需要使用者拍板的事，不是我能決定的。

## 2026-07-06 · L2 底部「關卡步道」進度條——寫了 v1 生圖規格，這次真要生 3 張

使用者要把 L2 填空底部那條進度條（我之前只是 CSS 近似版：綠色填充條+emoji🏁+蹲姿獵人當標記）升級成參考圖那種木質繪本闖關步道——木頭+草地小路、沿路等距圓形關卡節點、一個奔跑姿小獵人跑在當前節點、右端終點旗/營地。參考圖其實來自 L4 畫面。

盤點下來這次不像 L3 那樣 0 生圖，得生 3 張：(A) 步道底圖橫幅、(B) 奔跑姿獵人 sprite、(C) 終點旗/營地。關鍵是我去查了獵人 sprite 家族，發現現有 5 張（h1/h2/aim/idle/release）全是拉弓/瞄準/放箭姿，沒有一張跑姿，所以朝右跑的小人一定得新生——這點很容易被漏掉（以為沿用現成就好）。關卡節點圓帽跟題號木牌我判成 CSS 就能做，不生圖，省額度。

生獵人跑姿時我特別在 prompt 裡強調「維持與現有蹲姿獵人同一角色設定」（同髮型/頭帶/米白短衣素色滾邊/箭袋），並在 negative 裡把 drawing the bow/aiming/kneeling/shooting 都排掉，免得 Codex 又生一張拉弓的。文化安全照舊：獵人維持通用弓箭手無紋面無族群織紋，旗幟跟圓節點的 negative 特別加了「NO woven diamond pattern / ancestral eye motif」——因為旗面跟圓形徽章最容易被 AI 自動填上織紋圖案，這是我從關卡圖示紅菱形那次學到的教訓，主動防呆。

規格寫進 `Truku_ProgressTrack_Codex_v1.md`，三張 prompt 都報給主管轉使用者確認額度了，還沒真生。整合我也寫清楚了：步道底圖疊進 `#hunterTrack` 當背景並加高、節點 CSS、`#trackGoal` 換旗、`#hunter` 在 blank-active 換跑姿 src——分別交小排版跟小工程，我不碰 HTML。

建議：這條步道設計成可重用（命名中性 v2-progress-track 而非 v2-l2-track），先只 L2 啟用，日後小工程放寬顯示條件就能給 L3/L4/L5 共用，不用重生素材。畢竟參考圖本來就是 L4 的。

交棒：等使用者確認額度後，Codex 產出三張回收到 public/images/ui/，我要驗四項（透明 alpha=0 / 比例 / 無夾帶文字 / 文化），尤其 B 獵人要確認真的是朝右跑姿而非又一張拉弓、C 旗幟要確認沒被畫上菱形織紋。過了才通知小排版+小工程接整合。

## 2026-07-06 · 全站去 emoji 盤點——寫了 v13 icon 套組規格，也擋下一堆「不用生」的

使用者下了很強的鐵律「網頁不能出現任何 emoji」。我掃了桌機 hunter-truku-v2.html（5866 行）跟手機 mobile.html，把畫面上會渲染的 emoji 逐一分類。這次最重要的判斷不是「要生什麼」，而是「哪些其實不用生」——省額度、也避免重工：

1. **動物 fallback（🐗🦌🐿🦅🐒🐻🐆）我一開始差點列進生圖清單**，但去比對了 public/images/ui/ 才發現這 8 隻的 prey-*.png 插畫早就有了（山豬/水鹿/山羌/飛鼠/老鷹/猴子/熊/雲豹全齊）。所以這批是「小工程把 fallback 指向現成 PNG」，我一張都不用生。這是我從素材總清單職責養成的習慣：生圖前先查庫存。
2. **純符號（✓✗▶●□⌄▾➤⭐⬇✕）全歸小工程 CSS/SVG**，我不出圖。只有 ➤ 飛箭跟 ⭐ 星等我備註「日後想要木質感可再議」，但本批先向量。⚠ 大多在註解/console，標「非畫面・略」。
3. **真要我生的只有 10 張**：1 張缺圖預設 placeholder（最優先，止血約 46000 筆的 🎯 fallback）+ 9 張 UI icon（發音/提示/獎盃/玩家/登出/刪除/回顧/HP心/準星徽章）。

placeholder 我特意設計成「木質同心圓準星靶」而非任何動物——因為它會套在所有缺圖詞上，畫成動物會誤導詞義，這點在 prompt 跟 negative 都寫死「NOT any specific animal」。9 個 icon 統一成「圓木盤+金邊+中央符號」，刻意跟現有 v2-audio-button-wood.png 同一家族，不然去 emoji 後會變成一堆風格不一的雜牌 icon。

文化安全這批低風險（全是通用功能符號，人像 icon 也只是抽象半身剪影不涉服飾/紋面），但我 negative 照舊把菱形織紋/祖靈眼/紋面/其他族群圖騰全排掉——因為圓形木徽章最容易被 AI 自動填織紋，這是關卡圖示紅菱形那次學到的防呆，能加就加。

規格寫進 Truku_DeEmoji_Icons_Codex_v13.md（版本序接 v12 進度條），也複製一份到 Codex/02-game/。我沒動任何 HTML/JS，整合（emoji 換 img、textContent 改切 class、fallback 指路徑）都寫清楚交小工程/小排版。

留了三個要主管/使用者拍板的點：①icon 要不要帶木盤（還是純符號更輕量）②L2 提示卡 🎯 徽章要不要獨立生 I9 還是複用 placeholder 縮小 ③剩下沒現成圖的自然物 emoji（🌲🔥💨☀🌏）要不要開 v14 生。

交棒：等使用者確認額度，Codex 先生 placeholder 單獨確認風格 OK，再連生 9 icon（最好一次連續生確保木盤一致）。回收後我驗透明 alpha=0 + 小尺寸辨識度 + 無夾帶文字 + 文化，過了才通知小工程/小排版接。動物 fallback 那 8 隻記得提醒小工程「別再生，直接指 prey-*.png」。
