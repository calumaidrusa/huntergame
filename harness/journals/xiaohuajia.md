## 2026-07-02 · 從 v1 扁平向量換成 v2 細緻繪本風

一開始我照使用者最早的偏好，把所有素材都走扁平向量插畫風（乾淨線條、單一淺色背景），詞彙插畫也是這樣做的。後來使用者拿了一張參考 mockup 要整個重畫，一開始我以為連詞彙插畫都要跟著換，但使用者很快更正了範圍：**詞彙插畫維持原樣（klokah.tw 外連或既有的 v1 生圖），只有遊戲介面本身（背景、獵人角色、木牌/羊皮紙 UI 框架）換成 v2 風**。我把這條界線寫進了自己的職責規範，因為這種「兩套風格並存」的情況很容易在後續工作中搞混，我後來也真的差點犯了這個錯，得靠這條界線提醒自己。

交棒：任何新素材需求進來，先問「這是詞彙插畫，還是遊戲介面素材」，兩者適用不同風格規則。

## 2026-07-02 · 建立太魯閣族文化安全審查框架

使用者的詞彙表裡有不少實際的傳統器物/服飾詞（`pala` 布裙、`towkan` 背網、`bhniq` 弓等），我意識到這些如果隨便生圖很容易踩到文化挪用的雷。我參考了使用者提供的阿美族視覺文化守則的「流程結構」，但內容整個改寫成太魯閣族專屬版本——絕對不能把阿美族的紅黑配色、情人袋這些事實直接套到太魯閣族身上，那正是原文件警告的「跨族群混用」錯誤。我定了幾條硬紅線：不畫紋面（Ptasan）除非明確確認、不跟泰雅族菱形織紋混用、不跟其他族群符號混用、不確定的文化細節寧可省略也不編造。這套框架後來在好幾次生圖決策裡都被我拿出來用，尤其是關卡圖示那次差點踩雷。

## 2026-07-05 · 上線前視覺總審 + 診斷「logo 跑掉」的根因

使用者說「視覺上線不能再有遺漏」並回報「選擇 level 那個頁面 logo 跑掉了」，要我分析。我讀了程式碼發現：首頁用一張整合好的 PNG 招牌，但關卡選擇頁是另一套做法——空木牌背景 + CSS 疊字 + 一個用 `position:absolute; left:-108px` 掛在木牌左外側的獨立獵人圖，這隻獵人在窄一點的視窗下會被 `overflow:hidden` 裁掉，這就是「跑掉」的根因。我建議最乾淨的解法是關卡頁直接改用首頁那張整合圖（兩頁一致），但那張圖底部烤死了「太魯閣語」字樣，跟現在 42 語別可切換的情境衝突，所以同時建議連底部那行也一起去掉重生。使用者採納了，我依 v11 規格報了完整的 Codex prompt（含 negative prompt 明確排除各族織紋/紋面/PANGCAH 字樣），使用者拿去生成回收後，我做了三件驗收：圖裡只有兩組文字（族語射手/TRUKU WORD ARCHER）、透明背景四角 alpha=0、比例落在約 2.3:1，確認過關才交給小排版做 A1 換圖。

同一輪我也掃了一遍其餘素材（獵人角色、5 個關卡圖示、木框/沙漏/喇叭）確認無文化風險，唯一的風險點就是「別誤採 mockup 那個紅菱形」。
