# 小排版的工作日誌

> 第一人稱，格式見 [`../H-agent-journals.md`](../H-agent-journals.md)。這份是 2026-07-05 promote 時，
> 依當時的 memory / DEVLOG 回溯補寫的歷史紀錄，之後的新條目由我（下一個接手小排版的自己）繼續往下寫。

## 2026-07-02～04 · 兩輪整體美術風格改版

我先把畫面照使用者給的參考圖做過一輪「古地圖探險風」，後來使用者又要求改成「鮮豔叢林冒險風」，我重做了一輪配色與裝飾語言（金黃/深綠/木質棕、木雕邊框、羊皮紙卡片）。這段時間我學到一件事：使用者的視覺品味會反覆迭代，不要在第一版就把所有裝飾細節焊死，CSS 盡量留一點可以整批調色的彈性（雖然這專案沒有 CSS 變數，色值是寫死的 hex，但至少我把同性質的元件配色寫得盡量一致，方便之後整批替換）。

## 2026-07-04～05 · 五玩法選項關版面（L1/L4 共用）

小工程把選項點選流程做好之後，我接手把 `#choicePanel` 的版面排出來：木框背景配半透明黑遮罩內襯、上排線索區+沙漏計時、下排 2×2 選項網格。中間卡了一個有趣的問題——選項面板置中的話，左緣會整個壓在獵人身上，我後來改成「面板在獵人右緣以右的剩餘空間內置中」（`left: calc(240px + (剩餘寬)/2)`），不管螢幕多寬都能穩定讓出獵人的位置，同時把獵人的 `z-index` 抬到面板之上當雙重保險。選項數從一開始的 5 個，後來使用者拍板改成 4 個配 2×2 剛好對稱。

## 2026-07-05 · 選項關底部留白 + L1 遊戲說明看板

選項關（L1/L4）把底部打字輸入列隱藏掉之後，畫面下面空出一大條沒用的叢林背景——這是使用者標出來的問題。我的解法是把選項關的 `#stage` 從「保留 100px 底部間距給輸入列」改成「吃滿整個高度」，讓中央面板、地面、底部資訊列都跟著往下補實，這樣視覺重心自然平衡，不需要另外加裝飾物填空。

同一批我照小工程給的規格做了 L1 的海報式「遊戲說明」看板——大木牌標題、中央縮小版遊戲畫面預覽、四張編號說明卡配箭頭、底部目標木條。後來使用者又要求 L2-L5 也要做成一樣的海報式（原本只有 L1 是海報式、其他關卡是簡單羊皮紙卡，落差很明顯），我把整組 DOM 改成資料驅動——中央預覽區域按 mode 換內容（喇叭/提示卡/圖框/中文詞），四張卡的文案也是動態填的，全部沿用現成素材跟 CSS，沒有新生圖。

## 2026-07-05 · 關卡選擇頁完整改版 + 登出按鈕被切掉

使用者給了完整的關卡選擇頁 mockup：木招牌標題、語別下拉、5 張直式木框關卡卡（配色分級、圓形圖示、開始挑戰鈕）、底部石質功能列。我照著做了一輪完整版面。但第一次只換了圖示、沒有真的照 mockup 重排版面，被使用者抓到「沒有變」，我才發現自己派工時沒講清楚範圍——這件事讓我學到：使用者說「要像這樣」貼 mockup 的時候，要假設是要整個版面重排，不能只做局部代換。

後來 logo 統一（首頁跟關卡頁改用同一張整合圖）上線後，使用者又回報「登出按鈕被切到了」。我量測發現：新 logo 用 480px 寬渲染時高度到 171px，比舊版的 CSS 文字標題（約 70px）高了快 100px，把下面的五張關卡卡片跟底部功能列一起往下推，功能列的底緣超出了畫面固定的 540 高度，被 `overflow:hidden` 裁掉。這類「畫面高度是固定值、換了一個更高的素材就會把後面的東西擠出邊界」的問題，我後來會養成習慣：新素材尺寸確定後，先用固定容器高度倒算一次會不會超出，不要等使用者發現才回頭修。修法是把 logo 容器寬度收窄（480→360px），讓整組畫面重新落回 540 高度內。

## 2026-07-05 · L2 填空版面、特殊字元列、語別選單 hover bug

L2 填空最後定案的版面是：右側純提示卡（打散字母磚鷹架）+ 中央下方一排答案格（打字依序填入）+ 送出鈕，我把小工程給的穩定 id（`#hintLetters`/`.hint-letter`/`#answerCells`/`.answer-cell`）套上木質凹槽跟散字母漂浮的視覺。特殊字元列我做了跟遊戲整體一致的木質按鈕樣式。

語別下拉選單那個「要按著滑鼠才能選」的 bug 很值得記一筆：我原本在 `.lang-select:hover` 上加了 `transform:translateY(-1px)` 做一個很輕微的浮起回饋，結果這個 transform 讓 Chromium 對原生 `<select>` 的下拉互動整個壞掉——一放開滑鼠選單就收起來。這件事我在自己的沙盒環境完全重現不出來（原生下拉是瀏覽器/OS 層渲染，不是我的 DOM 能控制的），只能靠邏輯推斷「transform 加在 select 上」是嫌疑最大的東西，改成用 `filter:brightness()` 代替。以後碰到原生表單控制項（select、input[type=file] 這類），hover 效果我會直接避開 transform，改用 filter/box-shadow/border-color，省得再踩一次。
